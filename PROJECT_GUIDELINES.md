## 3. Dataset Schema & Domain Rules (Airfoil Self-Noise)

The raw file `../data/airfoil_self_noise.dat` is whitespace/tab-separated **without headers**. Always load it using relative paths and assign these exact column names:

| Column Name | Role | Physical Meaning | Unit |
| :--- | :--- | :--- | :--- |
| `frequency` | Feature ($X_1$) | Acoustic frequency of the measured noise | Hz |
| `angle_of_attack` | Feature ($X_2$) | Angle between airfoil chord line and free-stream flow | Degrees ($^\circ$) |
| `chord_length` | Feature ($X_3$) | Physical length of the airfoil section | Meters (m) |
| `free_stream_velocity` | Feature ($X_4$) | Velocity of the undisturbed airflow | m/s |
| `suction_side_displacement_thickness` | Feature ($X_5$) | Boundary layer displacement thickness on suction side | Meters (m) |
| `scaled_sound_pressure_level` | **Target ($Y$)** | Measured acoustic pressure level | Decibels (dB) |

### Critical Domain & Anti-Data-Leakage Guardrails (MANDATORY)
1. **Experimental Grouping (Anti-Leakage):** The dataset consists of frequency sweeps across fixed aerodynamic configurations (`['angle_of_attack', 'chord_length', 'free_stream_velocity', 'suction_side_displacement_thickness']`).
   * **NEVER** rely solely on a naive random `train_test_split` or `KFold`, as it leaks identical aerodynamic configurations across train and test sets.
   * Always implement and compare a group-aware validation strategy (`GroupKFold` / `GroupShuffleSplit`) grouped by aerodynamic configuration alongside standard CV to audit generalization across unseen operating regimes.
2. **Pipeline Encapsulation:** All scalers (`StandardScaler`, `PowerTransformer`), imputers, or feature transformers **must** be fitted exclusively inside a `scikit-learn` `Pipeline` / `ColumnTransformer` after splitting. Fitting on the full dataset before splitting is a disqualifying error (caps technical grade at **10/20**).
3. **Reproducibility:**
   * Use **relative paths only** (e.g., `../data/airfoil_self_noise.dat`, `../report/figures/`).
   * Set deterministic seeds (`RANDOM_SEED = 42`) everywhere (`numpy`, `random`, `scikit-learn`, `torch`/etc.).
   * Pin all package versions in `requirements.txt`.
4. **Statistical Rigor:**
   * Always run normality tests (e.g., Shapiro-Wilk) before choosing between Pearson and Spearman correlations.
   * Check for multicollinearity (e.g., `angle_of_attack` vs. `suction_side_displacement_thickness`) and skewed distributions (e.g., `frequency` spanning orders of magnitude $\rightarrow$ evaluate $\log_{10}(\text{frequency})$).
   * Never blindly drop outliers without physical/statistical justification.

* Define the aerospace/defense business case and formalize the supervised regression problem.

### Step 2: Standard Solutions & Baseline (Week 2 — 25% of grade)
* **EDA:** Data quality checks, descriptive statistics (mean, std, median, IQR, skewness, kurtosis), normality checks, correlation matrices, and physical visualizations with proper units.
* **Validation Protocol:** Define leakage-free train/validation/test splits (`GroupKFold` vs. `KFold` audit).
* **Baseline & Benchmark:** Implement a simple baseline (e.g., Multiple Linear Regression / Ridge) with residual diagnostics (normality, homoscedasticity) and state-of-the-art literature benchmarks ($\text{RMSE}$, $\text{MAE}$, $R^2$).
* **AutoML Pipeline (v0.1):** Evaluate standard model families (SVR, KNN, Decision Tree, Random Forest, Gradient Boosting) using a unified evaluation protocol.

### Step 3: Model Improvement & Beyond-Syllabus Algorithm (Week 3 — 30% of grade)
* **Iterations (v0.2, v0.3, ...):** Analyze v0.1 failure modes and introduce physics-informed feature engineering (e.g., dimensionless Strouhal number $St = \frac{f \cdot c}{U_\infty}$ or $St_{\delta^*} = \frac{f \cdot \delta^*}{U_\infty}$, Reynolds number proxy $Re \propto U_\infty \cdot c$).
* **Ensemble Learning:** Combine diverse model families (e.g., Stacking or Voting Regressor).
* **Beyond-Syllabus Algorithm (v0.4):** Implement an advanced method not covered in class (e.g., **Gaussian Process Regressor / Kriging** with composite kernels for built-in uncertainty quantification, or a regularized **Deep Neural Network / MLP**).
* **Scientific Reference:** Justify the beyond-syllabus algorithm with peer-reviewed literature (e.g., Brooks, Pope & Marcolini, 1989; plus recent Google Scholar papers on ML/Kriging/ANN for airfoil self-noise).
